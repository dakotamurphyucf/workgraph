# workflow.work_ticket

Generated from `workgraph discover --catalog`. Do not edit this file.

Record a real invocation, acquire admitted work and retain its actual ownership token through completion.

**Use when:** A harness has provisioned a worker that needs a durable ticket execution loop.

`workgraph help workflow.work_ticket` · [Focused reference](../coordination.md)

1. The harness provisions and supervises the process and checkout; register that actual invocation with run.register and retain its run revision.
2. Read ticket.context and ticket.readiness with target_run_id; inspect instructions, amendments, path ownership and policy before acquiring work.
3. Save ticket.start for the chosen ticket, or ticket.claim_next for selection, with the actual target run and an attempt ID when recording a try. Inspect the returned kind before using any token.
4. Retain the returned ticket token and attempt/lease revisions; record ticket.progress and handoff.set under current ownership, renewing timed ownership explicitly when needed.
5. Run the actual work and checks through the harness, satisfy applicable gates, then save ticket.finish with the actual token and concrete evidence. Report only observed completion.
