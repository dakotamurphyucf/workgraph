# workflow.recover_work

Generated from `workgraph discover --catalog`. Do not edit this file.

Inspect retained work and exact saved requests before any guarded ownership recovery.

**Use when:** An invocation ended or became stale and another harness must decide how to resume safely.

`workgraph help workflow.recover_work` · [Focused reference](../path-conditions-recovery.md)

1. Read ticket.resume and actor.overview or coordinator.overview to recover recorded instructions, handoff, held claims and attempts. Stale observations and expiry never prove process termination.
2. For an uncertain write inspect the saved journal and use retry on the exact saved request; do not refresh guards or replace its mutation identity.
3. The harness must stop or isolate the old execution and checkout before reclaiming its logical ownership.
4. Read current ticket.context or reservation ownership and retain the exact old token, lease revision and other required recovery guards.
5. Save ticket.recover with explicit disposition:requeue when work should return to Todo, or use the exact named/path reservation recovery method. Read retained recovery audit before starting replacement work.
