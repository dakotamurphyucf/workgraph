# input.changed

Generated from the CLI request and result definitions. Do not edit this file.

Record that an exact pinned input has been superseded, retaining the changed-input evidence.

Tier: `advanced`. The result is `{data, meta}`; see [common envelopes and types](common.md).

| Input | Presence | Type and constraints |
| --- | --- | --- |
| `actor_id` | required | string; max UTF-8 bytes=96; 1..96 ASCII letters, digits, underscores or hyphens |
| `current` | required | tagged alternatives; see complete schema |
| `mutation_id` | required | string; max UTF-8 bytes=96; 1..96 ASCII letters, digits, underscores or hyphens |
| `previous` | required | tagged alternatives; see complete schema |
| `run_id` | optional | string; max UTF-8 bytes=96; 1..96 ASCII letters, digits, underscores or hyphens |
| `workspace_id` | required | string; max UTF-8 bytes=96; 1..96 ASCII letters, digits, underscores or hyphens |

For preconditions and a small example, run `workgraph help input.changed`. Use `--full` for the complete contracts below.

**Use when:** A harness detected new input and must make its impact explicit for downstream reconciliation.

**Capability:** [verification](../discovery/capability.verification.md).

**Related:** [reconciliation.list](reconciliation.list.md), [reconciliation.record](reconciliation.record.md), [manifest.get](manifest.get.md).

**Effect:** mutation. Changes durable state using a saved request identity, so an exact retry can recover its receipt.
