# Declarative configuration foundation

This module validates the reviewed four closed v1 shapes and builds captured publication/query helpers. It does not provide the custom-view editor, invoke writes, replace a working view, fetch schema URLs, or execute supplied code. `ui-v-editor` owns the actual builder and adapter integration.

Use `decodeConfigSource(processing, bytes)` for bounded activation. It uses the owned protocol worker, enforces 64 KiB, duplicate/Unicode/tree limits, retains exact numeric lexemes and preserves unsupported versions for Raw/generic fallback. Structural validity alone is not activation: source/scope/field/filter/order semantics also apply. `configJson` emits only the closed shapes; unknown v1 fields cannot pass through an editor unnoticed.

`initialQuery` builds an initial native query only. The owning source adapter must retain its actual namespace capture, endpoint generation, query and continuation together. Filter mode `loaded` sends no local predicates to the server. `loadedOnly` also marks non-native sorting. Show “Loaded items only” while captured pages remain; never describe a sorted page as a global ordering. `LoadedRow.fields` are explicit typed adapter projections (numeric fields use exact numeric JSON lexemes); they are not arbitrary entity internals. `sourceContracts.fields` lists projected row values only. Native query options (`include_archived`, ticket/discussion `text`, ticket `label_id`) are server selectors, not row columns or loaded predicates; they are rejected in those positions. The editor must project every other declared row field explicitly rather than silently expose native internals. Pointers select only the adapter's fact value or explicitly decoded resource value.

Use `projectSessionRow` on validated native `SessionRecord` values: `created_at_unix_ms` / `last_event_at_unix_ms` become exact numeric Unix-millisecond adapter fields `created_at` / `last_event_at`. Null or invalid timestamps remain unknown. Loaded time ordering uses exact integers (and nanoseconds for explicitly supplied strict ISO UTC values); only timeline placement converts in-range milliseconds to a Date-compatible number. Out-of-range native int64 dates remain exactly sortable but occupy Unknown time. Native attempts have no creation timestamp: the earlier design table's planned `attempts.created_at` capability is not available, and attempt timelines/sorts on it are rejected rather than fabricated.

Server session sorting has one order: session ID ascending, or creation/last-event time descending. Compound or reversed sorting requires loaded mode. A timeline's first sort field is its explicit timestamp field; show that field in the view/editor. Invalid or absent timestamps occupy “Unknown time”. Ticket boards require status grouping. Discussion `scope` is a scalar scope _kind_: workspace/project must match the explicit view scope, whose project ID supplies the native tagged identity. Ticket server text is at most 256 UTF-8 bytes; discussion text 512; fact prefix 128 and scalar predicates 4096 encoded bytes. Loaded text filters retain the generic 512-byte bound.

`createConfigStore({http})` owns an independent Resources client/verified transfer and one active read. Reject oversized pins before download; retain exact resource/content-version/digest/size and original endpoint/workspace. It never selects a different Resources page. `readCatalogEntry` additionally checks the actual decoded kind/ID against the catalog row. An invalid or unavailable next capture must leave the host's working configuration unchanged; retain its selectable pin and Raw source rather than fall back to current. Multiple implicit renderer matches stay generic with an explicit chooser. Passive formatting returns data only; the host uses its normal escaped text/ContentViewer path and retains source and mutation warnings.

Publication is an explicit captured intention. Generate distinct config/catalog resource IDs and an intention ID once before suspension. Resource link target is independently workspace/project; the `ui.config.index` fact may use any supported explicit fact scope. Both belong to the same captured connection/workspace. Never promote ticket/milestone scope into a project link. `publicationBase` accepts complete metadata captures and separates metadata revision from latest content/version count. Existing document/catalog metadata bases retain their exact endpoint generation, workspace and observed link target; preparation rejects guard transplantation across these captures, including same-ID resources. Existing catalogs require their verified bytes and exact pin, checked again against the guarded base; new catalogs start explicitly empty.

`prepareConfigPublication` serializes a captured v1 document and replacement catalog, computes exact byte/digest pins and predicts content versions from version counts. It emits at most five explicit native transaction operations, omitting links already present. Resource publication increments metadata; a needed link uses the following guard. Index publication has its own captured fact revision. No generic JSON alias interpolation is used. Local invalid input throws `ConfigInputError`; worker cancellation/busy/timeout/protocol outcomes throw `ConfigProcessingError` with their exact kind; unexpected errors propagate. Register the returned Preparation with the application-owned OperationController, then expose ordinary Review/Apply. An uncertain outcome retains the same preparation/identity for explicit inspect/exact retry; do not rebuild, refresh guards or replace the working view automatically.

The foundation's helper browser proof uses real dedicated workers and native Resources reads. It is not proof of a working custom-view builder. Final editor/view integration must supply actual source projections, bounded captured paging, Raw/generic fallback, persistent draft/operation ownership, explicit renderer selection and real product UI workflows.

Native source correction: `thread.list` does not return a thread owner `actor_id`. That name remains a supported server query selector, but is unavailable as a projected column, loaded predicate, sort or grouping. Older source using those unsupported row capabilities remains available as Raw/invalid configuration; the editor must never invent ownership or activate it silently.
