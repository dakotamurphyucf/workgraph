# Coordination workspace

`ParticipantsWorkspace` keeps the accepted People and runs view and adds allocation,
reservations, outside conditions and recovery records. The application creates one
`CoordinationController` for the launch and disposes it before the shared protocol
processor. Navigation never changes a retained form's endpoint generation, workspace,
writer, target or ownership guards.

Ordinary forms use the shared OperationController: Review captures current complete
catalog guards and prepares a saved request; Execute sends it explicitly. Run limits,
actor records and invocation capabilities remain in People and runs. Pool and ticket
policies are cooperative admission rules, not authenticated credentials.

Named and logical-path batches are atomic. Paths are lexical scopes in an explicit
worktree; they do not enforce filesystem access. Renew/release captures actual owner,
run, token and lease revision. Automatic borrowers remain visible and cannot use
ordinary release. Expiry does not free ownership or prove that a process stopped.

The optional bounded acquisition wait has a separate native service-local intention
namespace. Its `wait_prepared` form cannot switch to an ordinary operation. Rechecking
preparation repeats the exact complete plan without starting it. Start, Cancel and
Retry exact are explicit. The native helper reuses Reservation_wait.collect, saves
every actual attempt journal before exchange, bounds deadline/attempts/feed reads,
and keeps one flight including exact retry. Restart never resumes a saved flight.
Canceling a retry cannot resolve its original unknown outcome; a validated durable
grant wins a racing cancel. Browser observers own only finite GET reads. Saved waits load one complete job per
explicit page, with Next and Refresh controls and the native remaining count from
that read. Already inspected jobs remain by ID; a first page never establishes a
complete catalog. Each card distinguishes its original target from the current
selection. No page restores or starts a flight automatically. An individual job
that exceeds the existing 16 MiB response budget fails explicitly; no outcome or
journal is silently clipped. Public outcomes include compact journal references
and one exact retry request, not the full stored request array. Attempt counts
count started exchanges; a saved journal may remain unstarted at a deadline.

Outside conditions bind a declaration revision, external operation and exact proof.
Signals record attributed observations, not external execution. Guarded recovery
requires an explicit operator observation that the original owner was stopped or
isolated, a reason and the captured old-owner/token/lease fences. Neither a stale
heartbeat nor lease expiry supplies that observation. Historical audit summaries
retain their original operator, binding, proofs and lossless source.

Editor inputs are copied synchronously before awaits, with certified immutable JSON
sources retained by reference and charged against 4 MiB per draft / 16 MiB aggregate.
Catalog continuation retains actual endpoint and namespace revision; incomplete
catalogs never establish absence. Expired/cleared holder notes may be hidden, so note
revision is explicit rather than inferred as zero.

Focused checks run with `node node_modules/vitest/vitest.mjs run
 tests/participants/coordination` from `ui/frontend`. The maintained Playwright
`coordination.browser.ts` uses the embedded production application and disposable
real daemon/companion fixtures, DOM actions, independent CLI readback and strict
console/network diagnostics. `schema.browser.ts` compares all structured command
variants with schemas from the selected real executable. Native expect tests cover
publication barriers, exact retry, cancellation races and durable replay. Feature
qualification and supported-platform results must be recorded separately; source
presence alone does not establish acceptance.

## Presentation and refresh ownership

Catalogs occupy the full collection width. Actions open a modal; closing it only
clears the selected draft ID, preserving the central controller's captured author,
scope and guards. Saved waits and retained drafts use secondary disclosures.

Catalog rows use validated native entity identities, not namespace revisions, as
React keys. A same-query background read keeps the previous page visible, so
expanded source details survive a newer capture. Invalid rows use isolated index
keys and never supply a trusted identity. A new endpoint, workspace, method or
page still follows the read-slot boundary. The explicitly opened contention
inspector follows live updates; continuation pages remain pinned. Neither path
starts a wait or issues a write.
