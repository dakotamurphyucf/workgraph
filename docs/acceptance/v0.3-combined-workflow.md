# Workgraph 0.3 combined workflow acceptance

On 2026-10-09, one fresh isolated workflow passed using the current source-tree
CLI on macOS ARM64. It used separate worker/reviewer contexts and private request
directories, a local daemon, and a second registry for restore. The stable tracker
was not used. Runtime was 8.399 seconds. The harness recorded 64 CLI calls;
the production recipes also retained their individual request/response records.

Commands actually executed included:

```sh
./dev build --build-dir=_build-local-io bin/main.exe
python3 scratch/agents/v03-local-io-20261009/combined-workflow.py
python3 examples/gated-review-workflow.py "$WG" "$SOCKET" combined "$REVIEW_STATE" \
  --prefix two-round --worker worker --reviewer reviewer
python3 examples/capacity-rollover.py --binary "$WG" --socket "$SOCKET" \
  --actor worker --predecessor combined --successor successor \
  --successor-root "$SUCCESSOR_ROOT" --export-directory "$ROLLOVER_EXPORT" \
  --state-directory "$ROLLOVER_STATE" --selection "$SELECTION" --writers-quiesced
```

The orchestration script and raw logs remain private in `scratch/`. Both public
recipes were executed twice against the same saved state, with identical results.
The source-tree executable SHA-256 was
`202f3f67ea6bcc70bb7505f0f9123741f61a10e9a4ba9c64f217c730e92231c3`.
This identifies the tested local binary, not a release artifact.

The successful fresh run had no unexpected API failures. An earlier scratch-runner
attempt stopped because it read the advisory meter as `percentage` instead of the
documented `percent_used`; the runner was corrected and the entire workflow rerun
against fresh data. No production change was made for that error.

This is descriptive combined CLI acceptance. It does not replace the full build,

evaluation, or a Workgraph-versus-Markdown context-reset comparison. No native
