regression evidence, not promises that every possible workload has been tested.

## Release acceptance boundaries

Every implementation ticket has a pinned source/report manifest and an actual
root review in the development workspace. The final candidate additionally requires
independent review, root review, full `./dev build @fmt @runtest @install`, a real
multi-actor workflow, source/skill inventory verification and native installed
qualification on macOS ARM64 and AlmaLinux 10 x86_64. These gates remain distinct
from a feature-level test pass.

The published release carries the exact source identity, commit, artifact hashes
and observed platform evidence. This source document deliberately does not embed
its own final commit/hash: changing it would change the source being qualified.
Use the matching release evidence and `SHA256SUMS` to identify the tested bytes.

The [release notes](../releases/v0.6.0.md) describe the breaking preview upgrade.
Only current formats are supported. SQL, automatic lock takeover/FIFO grants,
a model runtime, MCP and distributed scheduling are outside the accepted scope.
AlmaLinux container results do not establish Windows/WSL-kernel or SELinux-policy
qualification; macOS signing/notarization and Gatekeeper scope are stated in its
platform evidence. Historical qualification records are unchanged.
