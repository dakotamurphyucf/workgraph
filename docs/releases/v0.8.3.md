# Workgraph 0.8.3 — Smoother live navigation and readable uploads

This patch keeps the optional browser UI connected across compatible page switches
and background tabs, makes recovery faster, and fixes text uploads appearing as
binary files. It retains the change-driven refresh and complete actor choices
introduced in 0.8.2.

## Live connections and recovery

- **Switch pages without reconnecting unnecessarily.** Pages watching the same
  workspace feeds reuse the active observation and its cursors. Changing the
  focused project does not restart the workspace observation.
- **Reuse connections when switching feeds.** When a different observation is
  needed, the browser asks the companion to cancel the old wait on the server.
  The original HTTP response finishes normally, allowing its socket to be reused.
- **Background tabs stay connected.** Changing tabs or windows no longer cancels
  observation. Returning to a tab does not trigger a saved-profile lookup or a
  full page refresh merely because it regained focus. Browser suspension and
  computer sleep can still interrupt execution; existing content is retained
  during automatic recovery.
- **One-second recovery delays.** Observation, page-refresh and saved-connection
  retries use a fixed one-second interval instead of exponential backoff.
  Browser timer throttling can delay execution in background tabs.
- **One immediate retry for failed reads.** Explicitly read-only requests retry
  a network transport failure once, with identical parameters. Writes are never
  automatically repeated through this path. Validation errors, protocol errors,
  cancellation and timeouts do not use the immediate retry.
- **Stalled reads have deadlines.** Saved-connection and observation-cancellation
  requests have ten-second network deadlines; other supported reads have
  45-second deadlines. These are request-duration limits, not retry delays.
- **More accurate status.** A page-refresh failure says “Refresh delayed” instead
  of implying that the live connection has disconnected. Page and observation
  failures are tracked separately and cannot compound retry delays.

Healthy idle tabs still use one long poll at a time, renewed after up to 25
seconds, without repeatedly rereading page data. Changes are batched for 250 ms.
The companion's independent 16-observation pool and bounded capacity fallback
remain in place. Drafts, historical captures, scroll position and write guards
retain their existing behavior.

## Resource previews

- **Markdown uploads render automatically.** An upload without an explicit MIME
  type is stored as `application/octet-stream`. The viewer now treats that as an
  unknown type rather than proof of binary content. Recognized filenames select
  Markdown or code rendering; other valid UTF-8 text defaults to Markdown.
- **Editing the type updates the preview.** Filename and MIME corrections now
  affect the matching current publication without another upload or download.
  The verified bytes, digest and content version do not change.
- **Consistent labels and historical views.** The resource list recognizes
  Markdown filenames even with a generic MIME type. Current preview labels and
  custom renderer selection use the same effective hints. Opening an older
  publication uses its recorded hints; an already open historical capture stays
  stable when a new publication arrives.
- **Real binary data stays binary.** Invalid UTF-8, binary control bytes and
  specific binary MIME types retain the binary view and exact byte download.

Existing uploaded files benefit from the viewer fix without being uploaded again.
No stored MIME values or resource contents are silently rewritten.

## Downloads and upgrade

Install the **0.8.3 core and optional UI together**. The companion and daemon
package versions must match. Downloads include core-only and paired UI tar
archives for Apple Silicon macOS and AlmaLinux 10 AMD64, AlmaLinux core/UI RPMs,
source, the standalone agent skill, checksums and qualification reports.
Installed operation requires neither Node.js nor opam.

**No data reset or migration is required from 0.8.0, 0.8.1 or 0.8.2.** Resolve any
uncertain operations using their original executable, stop your old UI and daemon,
and replace both executables with the matching release. Restart with the same
registry, workspace and UI state locations. Preserve saved request journals and
keep data outside the installation directory. Reload existing browser tabs so
they load the new companion's matching frontend. Update the bundled agent skill.

See [UI installation](../ui/installation.md) and the
[AlmaLinux/WSL quickstart](../wsl-quickstart.md) for commands. Check downloaded
files against `SHA256SUMS`. Earlier release assets remain unchanged.

Application API **0.7**, workspace/export format **6**, history batch format **2**,
saved upload plan **2**, and registry/planning event format **5** are unchanged.
Existing 0.7.0 data remains supported. The separate [offline converter](../migration.md)
continues to accept only the released 0.6.2 representation.

## Verification and platform scope

Regression checks cover safe read retries during headers and body transfer,
fixed retry intervals, cursor retention, background visibility, navigation,
server cancellation and reuse of the same HTTP socket. Real-daemon browser
scenarios check idle request counts, updates while hidden, three simultaneous
windows with repeated reloads, compatible page switches, and a real CLI upload
followed by live MIME corrections without re-downloading content.

Release qualification covers frontend checks, formatting, native build/test/install,
installed packages and installed-browser behavior. Attached reports record the
exact source, artifacts and observed platform results.

macOS packages are ARM64 and are not Developer ID signed or notarized. AlmaLinux
10 packages require an x86-64-v3-capable AMD64 CPU. Native Safari and
Windows-browser-to-WSL operation are not part of automated qualification.
