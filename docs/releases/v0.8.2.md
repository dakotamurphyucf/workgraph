# Workgraph 0.8.2 — Quieter live updates and complete actor choices

This patch makes the optional UI refresh when data changes, instead of repeatedly
rereading idle pages. It also fixes missing actors in recipient dropdowns. Actors
known through runs and workspace activity now appear even when they do not have
a separate actor-directory registration.

## Live updates without constant page polling

- **One long poll per visible tab.** Planning and history observation share one
  authenticated request, waiting for up to 25 seconds. Healthy idle tabs renew
  that request without rereading page data. Existing HTTP keep-alive reuses
  connections; this is long polling, not an EventSource stream.
- **Refresh when something changes.** A 250 ms batching window combines bursts
  into a refresh. Refreshes remain serial and keep existing content, drafts,
  historical captures, selection and scroll position in place.
- **More room for multiple tabs.** A dedicated pool supports 16 simultaneous
  observations, separate from ordinary reads, writes and the generic wait lane.
  Closing, hiding or reloading a tab cancels its previous observation and releases
  capacity. A full observation pool causes bounded fallback refreshes and retry,
  rather than leaving the tab waiting in a long queue.
- **Quiet reconnects.** Transient connection failures keep feed cursors and
  rendered content, retry with backoff, and catch up on recovery. They do not
  trigger page reloads or repeat writes. An invalidated cursor starts a fresh
  observation followed by a current-data refresh.
- **Time-dependent warnings still update.** For Overview, Participants and Saved
  views, the companion compares default stale-agent and expired-ownership warning
  states when observations return. An age increasing by itself does not cause
  page reads. Clock-only transitions can take up to one wait interval to appear.
- **No idle connection-directory polling.** Profiles refresh on initial load,
  explicit changes, returning to a visible tab and connectivity restoration.
  Failed checks retry with backoff.

## Complete actor choices

The Received Messages picker previously discarded participants without an
`actor.put` directory entry. A workspace could have active contributors and
received messages while the picker reported zero registered actors.

- **Choose actors known through activity.** The dropdown now includes those
  participants alongside registered people and agents. No extra registration is
  needed to select them and read their messages.
- **Clearer labels.** The picker says “known actors.” Activity-only identities
  are marked “seen in activity”; this does not imply a process is currently running.
- **Shared fix.** Other UI forms using the same recipient picker benefit too,
  including request recipients and actor filters.
- **Existing behavior preserved.** Registered display names remain visible.
  Explicitly archived registrations stay out of suggestions, while manual ID entry
  remains available for archived or unlisted recipients. Refreshing choices keeps
  the selected ID and does not change the acting author.

These changes do not register actors, grant permissions, modify messages, or
change the daemon application API or storage formats. The HTTP
connection-reuse improvements from 0.8.1 are retained.

## Downloads and upgrade

Install the **0.8.2 core and optional UI together**; companion and daemon package
versions must match. Both core-only and UI packages are available for Apple Silicon
macOS and AlmaLinux 10 AMD64, with tar archives and AlmaLinux RPMs. Installed
operation needs neither Node.js nor opam. Source, the standalone agent skill,
checksums and qualification reports are also included.

**No data reset or migration is required from 0.8.0 or 0.8.1.** Stop the old UI,
resolve uncertain operations with their original executable, and stop or hand off
the daemon before replacing the installation. Restart using the same registry,
workspace and UI state locations. Preserve saved request journals and keep data
outside the installation directory. Update the bundled agent skill as well.

See [UI installation](../ui/installation.md) and the
[AlmaLinux/WSL quickstart](../wsl-quickstart.md) for commands. Verify downloaded
files against `SHA256SUMS`. Earlier release assets remain unchanged.

Application API **0.7**, workspace/export format **6**, history batch format **2**,
saved upload plan **2**, and registry/planning event format **5** are unchanged.
Existing 0.7.0 data remains supported. The separate [offline converter](../migration.md)
continues to accept only the released 0.6.2 representation.

## Verification and platform scope

A real-daemon browser regression reproduced the missing choice before the fix.
With the fix, it checks selection and message retrieval for an activity-only actor,
registered display names, archived suggestions, refresh preservation and manual
ID entry. Live-update tests cover idle request counts, change-driven refresh,
combined feeds, cursor recovery, batching, observation capacity and cancellation.
Release qualification covers frontend checks, formatting, native
build/test/install, package installation and installed-browser behavior. Exact
artifact hashes and observed platform results are attached.

macOS packages are ARM64 and are not Developer ID signed or notarized. AlmaLinux
10 packages require an x86-64-v3-capable AMD64 CPU. Native Safari and
Windows-browser-to-WSL operation are not part of automated qualification.
