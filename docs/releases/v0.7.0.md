# Workgraph v0.7.0 preview

Version 0.7.0 addresses the eight reported history and usage problems and the
concurrent JSON parser defect found during investigation. It uses application API
0.7, workspace/export format 6 and history batch format 2. This is a breaking preview;
use matching client, daemon, skill and documentation.

## Changes

| Reported problem | Result in 0.7.0 |
| --- | --- |
| 1. Supplying even the current history head triggered full replay. | Current-head reads reuse the verified immutable capture. A bounded cache reuses resolved ancestors; cold reconstruction runs on a read worker. |
| 2. A transcript metadata page required one content request per event. | `history.payloads` reads primary payload prefixes for 1..100 exact event references under one head. Ordered results preserve duplicates and include per-item byte continuation. Missing references fail explicitly. |
| 3. Search and historical reconstruction congested ordinary reads and delayed writes. | Current/cached metadata and payload reads use a separate lane from search and cold historical reconstruction. Each lane admits at most 16 outstanding operations; serialized writes retain their own persistence path. |
| 4. Parallel history calls could fail with malformed or mixed JSON. | Every JSON decode and numeric-validation parse owns independent parser state across OCaml domains. Existing depth, size, duplicate-key, UTF-8 and number checks remain. |
| 5. Search coverage and continuation looked contradictory, and terminal pages retained `next`. | `index_complete` describes searchable coverage; `has_more` describes traversal. Terminal pages have `has_more:false` and `next:null`. Incomplete indexing exposes restart guidance rather than claiming absence. |
| 6. Sessions lacked durable creation/activity times and useful list order. | Session metadata has nullable `created_at_unix_ms` and `last_event_at_unix_ms`; append records have nullable commit times. `session.list` supports stable creation/activity order, unknown times last, ID ties and explicit run filtering. |
| 7. Creating a session with run attribution left run session reads empty. | `run.get/list` derive the sorted union of explicit links and captured session run attribution. A bounded preview has total/omitted counts and an exact continuation; `run.sessions` reads the full union. Stored run revisions and mutation receipts retain their original meaning. |
| 8. Separate metric rows made usage groups verbose. | `usage.aggregate` keeps `rows` as its default and adds `nested` complete metric groups and `totals_only` summaries. Names, units, filtering, overflow and capture guards remain explicit. |

The parser defect is **critical**: a shared mutable Jsonaf parser could mix parsing
state between concurrent domains, affecting request and persisted-data decoding.
The investigation reproduced incorrect parser results and request failures. It did
not establish that retained durable data had been corrupted. The correction removes
shared mutable parser ownership; it does not silently repair previously damaged files.
Preserve and inspect any affected data through ordinary integrity/recovery procedures.

## Captures, bounds and interpretation

Omitted `head` selects current history, a digest selects an exact retained ancestor,
and explicit null selects empty history. Keep the returned head for transcript pages,
payload continuations and session-list traversal. Run association traversal also pins
the stored run revision; run-list traversal pins the coordination revision and history
head. Association capture metadata may omit event watermarks: omission means they
were not included, rather than proving the workspace has no sessions.

Payload batches preserve bounded prefixes rather than promising full bodies. Continue
partial bodies through `history.payload` using the same head and returned byte offset.
The full public response, including Base64 expansion and metadata, must fit its budget.
Nested usage arrays are whole groups; `needs_larger_budget` and `required_bytes` report
when the next group cannot fit. For detail larger than the maximum budget, start a
`rows` query or select `totals_only`.

Read lanes have bounded admission, not a per-client fairness or latency guarantee.
A full lane returns a retryable `Conflict`; bound concurrency and back off. A timeout
never proves that an admitted write failed. Payload ranges still verify the complete
referenced blob. Captures larger than the cache budget remain readable but bypass it.
See the [history reliability design](../history-reliability.md) for ownership, caching,
scheduling and integrity boundaries.

New daemon timestamps are observed Unix epoch milliseconds, separate from opaque
provider/source timestamps inside imported payloads. Retries, duplicate-only appends
and archive operations do not invent new last-event activity. Clock regressions are
preserved, so timestamps do not establish causal order.

## Formats and API

| Representation | Current identifier |
| --- | --- |
| Application and saved request envelope | `workgraph_api:"0.7"` |
| Workspace descriptor | `version:"6"` |
| Workspace export and workspace-set export | `version:"6"` |
| Local registry | `version:"5"` |
| Planning transaction and event envelope | `version:"5"` |
| History batch | `version:"2"` |
| Planning HEAD, history HEAD, advisory heartbeat cache | `version:"1"` |
| Saved upload plan | `transfer_version:"2"`, inside a current API envelope |

Normal readers accept complete current shapes only. New formats are not accepted
by old binaries, and a new API marker does not make old saved requests current.
Read the [compatibility reference](../../skills/workgraph/references/compatibility.md)
for exact independent representations and failure handling.

## Upgrade from the supported 0.6.2 workspace format

Keep the old executable and archives before replacing an installed command. Resolve
uncertain writes with the **old executable, daemon and original saved request files**,
then stop all old writers and launchers. Preserve complete stopped roots, registry,
contexts, journals and exports.

The explicit offline converter accepts the released 0.6.2 representation: workspace 5,
planning transaction/events 5, planning/history HEAD 1 and history batch 1. Format
markers establish the accepted representation; they cannot prove which historical
patch executable wrote it. Earlier preview formats and arbitrary prototype schemas
are unsupported. There is no in-place startup conversion.

```sh
workgraph migrate --from 0.6.2 \
  --source /absolute/old-workspace \
  --destination /absolute/new-workspace
```

The destination must not exist. Conversion validates the source, preserves original
committed files, copies referenced content and verifies current-format replay before
publishing the new root. Planning transaction bytes, IDs, revisions, receipt identities
and planning heads survive. History hashes change when timestamps are added; the
report includes a mapping for every old history batch head. Reacquire cursors/captures
and translate an old read pin explicitly through that map. Ordinary reads do not alias
old digests.

Old creation and activity times remain **null**. They are not inferred from filesystem
times or opaque transcript timestamps. Use a fresh registry, socket, contexts and request
directory after migration; register the converted workspace there. The converter does
not migrate old registry jobs, unfinished uploads, request journals or old exports.
API 0.6 request files remain intact for their old binary and cannot be replayed unchanged
against API 0.7. Generate new exports from the converted workspace.

Follow the complete [migration guide](../migration.md), including ownership-checked
staging cleanup and publication uncertainty. A published destination must never be
removed or overwritten merely to resolve an uncertain acknowledgement.

## Qualification and limits

The release record must bind the final commit/source identity, complete integrated
gate, installed-platform checks and artifact hashes before publication is considered
qualified. Focused implementation tests and older release records do not qualify the
final 0.7.0 artifacts. See [validation](../validation.md) and the matching published
qualification records for observed evidence.

Platform labels alone do not establish runtime success. Container checks qualify the
reported AlmaLinux userspace on their host kernel; actual WSL execution needs its own
Windows-host check. macOS signing, notarization and downloaded Gatekeeper behavior
need separate evidence. Successful sync calls, process termination and injected failures
do not establish physical power-loss behavior.

No distributed writer coordination, model runtime, MCP server, history pruning or blob
garbage collection is introduced. The harness continues to own processes, prompts,
external side effects and provider spending.
