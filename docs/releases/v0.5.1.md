# Workgraph v0.5.1 preview — portable agent skill

Version 0.5.1 turns the bundled agent documentation into a portable Agent Skills
folder. It includes the full README, clear Markdown guides, all 259 API method
contracts and runnable helpers. The two broken README sequence diagrams are fixed.

**No data reset is needed when upgrading from 0.5.0.** Application API `0.5`,
stored roots `4`, mutation identities and durable data contracts are unchanged.
The executable changes only help text and documentation paths. This remains a
preview release, with the same local, cooperative operating model as 0.5.0.

## What changed

- `skills/workgraph/SKILL.md` replaces the XML-based `AGENT_GUIDE.md`. Its metadata
  lets a skill-aware harness discover it; the entrypoint introduces concepts and
  directs agents to the next relevant reference.
- Focused guides use ordinary Markdown. They explain workspaces, actors, runs,
  claims, revisions, captures and evidence before using them in workflows.
- The full README lives inside the skill too. Orchestrators can use its workflow
  examples and participant prompts when assigning work to subagents. A generation
  and test check keeps this copy synchronized with the repository README.
- The skill contains `references/api/` with all 259 generated request/result
  contracts, and `scripts/` with the dashboard, history, CI, notification and
  review helpers. Copy the whole folder so links and sibling imports keep working.
- The “Ask rather than guess” and “Independent review gates” Mermaid diagrams
  no longer contain the message-text semicolons that caused parsing errors.
  All 13 README diagrams were checked with a Mermaid parser.
- `fact.put` help correctly describes its revision guard as required. The API
  already required it; this corrects wording rather than changing behavior.
- Source, native and RPM packages include the complete skill and validate its
  inventory, links and agreement with the executable's API catalog.

## Upgrade from 0.5.0

1. Keep your current binary/archive and a verified backup of important data.
   Finish or retain exact pending request journals before restarting the service.
2. Shut down your daemon gracefully using its existing context:
   `workgraph --context /absolute/agent/context.json daemon shutdown`.
   Stop any custom supervisor that would immediately restart the old binary.
3. Download the new archive or RPM and `SHA256SUMS` from this release. Verify the
   checksum for the exact downloaded filename before installing or extracting it.
4. On AlmaLinux, install the verified RPM with
   `sudo dnf install ./workgraph-0.5.1-1.el10.x86_64.rpm`. On macOS, extract
   `workgraph-0.5.1-macos-arm64.tar.gz` into a new directory and update your PATH
   or explicit executable path. Keep each extracted bundle together.
5. Verify `workgraph --version` reports `0.5.1`, then restart with the **same**
   registry and socket: `workgraph serve /absolute/registry /absolute/daemon.sock`.
   Your existing contexts, workspace roots, exports and saved request journals
   remain valid. Do not delete sockets or ownership guards to force startup.
6. Install the new skill as described below, update old documentation/helper
   paths, and refresh your harness's skill discovery. Read back your current
   ticket and handoff before continuing work.

You can also install only the skill while retaining a 0.5.0 executable. Its API
contracts are the same; the older executable's help still points to older
reference paths. Preserve the new skill as a complete folder.

For **0.4 or earlier**, this patch does not add migration support. Follow the
[preservation-first 0.5 upgrade](v0.5.0.md#upgrade-from-04-or-an-older-preview),
then use the 0.5.1 packages. Keep the matching old binary with old data. No broad
deletion or hard reset is required for the 0.5.0-to-0.5.1 update.

## Install the skill

The standalone `workgraph-0.5.1-skill.tar.gz` extracts to `workgraph/`, containing
`SKILL.md`, `README.md`, `LICENSE.txt`, `references/` and `scripts/`.
Native tarballs contain it at `skills/workgraph/`; the AlmaLinux RPM installs it
at `/usr/share/doc/workgraph/skills/workgraph/`.

Copy the whole folder into your harness's configured skills directory. For a
harness using `~/.agents/skills`, first move an existing `workgraph` skill aside
without deleting custom changes, then copy the new folder into that location.
Give each worker the executable path, its own context and request directory,
assigned ticket/run identity and explicit file ownership. Orchestrators should
read the bundled README as well as the skill entrypoint.

See [skill installation](../agent-skill.md), [WSL quick start](../wsl-quickstart.md)
and [macOS installation](../macos-install.md) for complete setup instructions.
Existing v0.5.0 release assets and its tag remain unchanged.

## Qualification and limits

The release includes source/native manifests, `SHA256SUMS`, platform qualification
reports, an aggregate `qualification.json` and evidence archives. These bind the
release commit, source inventory, executable and artifact hashes. Check their
`status` and exact identities; older qualification does not qualify new bytes.

Validation covers the full formatter/build/test/install gate, copied-folder skill
validation, preservation of API schema constraints, packaged README synchronization,
real daemon/socket workflows and installed CLI/Git/export/restore/history checks.
An independent agent completed a workflow using only the copied skill and executable:
dependency blocking, shared facts/resources, a two-actor question and exact answer
retry, fresh-context recovery, completion and verified export.

AlmaLinux checks run in fresh x86_64 containers for both RPM and tar installation.
They qualify AlmaLinux userspace on the runner's kernel, not an actual Windows/WSL
kernel or SELinux policy. AlmaLinux 10 AMD64 requires x86-64-v3. macOS ARM64 checks
record their actual OS and deployment minimum; Developer ID signing, notarization
and browser-download Gatekeeper launch remain unqualified. Running either native
executable requires no opam or OCaml installation.

No model runtime, MCP server, authentication, distributed coordination, automatic
history compaction or garbage collection is added. Agent processes, prompt policy,
external side effects and enforcement remain the harness's responsibility.
