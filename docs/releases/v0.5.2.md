# Workgraph v0.5.2 preview — interactive WGX dashboard

Version 0.5.2 makes it easier to follow cooperating agents from your terminal.
WGX now has an interactive dashboard with focused views, readable details and a
Linear-inspired dark palette. The ordinary terminal commands also show richer,
colorized information.

**No data reset is needed when upgrading from 0.5.0 or 0.5.1.** Application API
`0.5`, stored roots `4`, saved request identities and daemon behavior are unchanged.
This is still a preview release for cooperative local workflows.

## What changed

- Five dashboard tabs: **Overview**, **Tasks**, **Questions**, **Agents**, and
  **Activity**. The overview highlights what needs attention and work in progress;
  technical details stay available without crowding the main screen.
- Spaced task cards, word wrapping, full terminal height and resize handling.
  Selection follows the same item across refreshes, and each view remembers its
  position. The dark theme uses charcoal surfaces, neutral headings, indigo
  accents and subdued status colors.
- Open a task for its description, acceptance criteria, ownership, comments,
  linked resource names and start/completion requirements. Open a question for
  its source message and pinned answer; inspect an agent's objective,
  capabilities and file reservations. Resource bodies are not downloaded.
- Questions, review requests and pending instruction acknowledgements are visible
  together. Readiness distinguishes graph dependencies from eligibility for an
  explicitly selected worker run. Checks still loading are clearly marked.
- Search, worker/resolver filtering, task-state filters, collapsible groups,
  dependency trees, inactive-agent filtering and a technical status inspector.
- Pause the displayed snapshot while reads continue. On resume, highlight records
  observed changing. This is an observation comparison, not a complete event log.
- Background reads keep navigation responsive. Failed reads retain the last good
  snapshot with a stale/reconnecting banner. Quitting cancels the active read and
  restores the prior terminal screen, colors and input settings.
- Richer `status`, `ticket`, `questions`, `agents`, `inbox`, `files` and `storage`
  output, including owners, timestamps, request titles, evidence previews and
  storage meters. `watch` renders readable events; `watch --metadata` retains the
  compact metadata view. `tree TICKET` prints declared prerequisites.
- `WGX_COLOR=auto|always|never` controls styling; a nonempty `NO_COLOR` disables it.
  Noninteractive/dumb terminals receive a plain status snapshot for `dash`.
- The complete skill bundle includes the Python dashboard companion, updated
  instructions and the synchronized README. WGX remains strictly read-only:
  viewing does not claim work, answer requests or acknowledge deliveries.

## Install

Download the matching package and `SHA256SUMS` from this release:

- AlmaLinux 10 x86_64: RPM or native tar archive.
- macOS ARM64: native tar archive.
- Source and standalone agent skill archives are also available.

See the [WSL/AlmaLinux quick start](../wsl-quickstart.md),
[macOS installation](../macos-install.md) and [skill installation](../agent-skill.md).
The native executable needs no OCaml/opam installation. WGX uses Bash 3.2+ and
jq 1.6+; the interactive dashboard and dependency tree also need **Python 3.10+**.
On AlmaLinux, install helper dependencies with `sudo dnf install -y jq python3`.
On macOS, `brew install jq python` supplies them if needed.

## Upgrade from 0.5.0 or 0.5.1

1. Keep the current binary/archive and a backup of important data. Retain pending
   request journals and any locally customized helper scripts.
2. For a full executable upgrade, gracefully stop the daemon using its existing
   context: `workgraph --context /absolute/context.json daemon shutdown`. Stop any
   supervisor that would immediately restart the old executable.
3. Download the new package and verify its exact filename against `SHA256SUMS`.
   Install the verified RPM with
   `sudo dnf install ./workgraph-0.5.2-1.el10.x86_64.rpm`, or extract the native
   archive into a new directory and update your executable path.
4. Verify `workgraph --version` prints `0.5.2`. Restart with the **same** registry
   and socket: `workgraph serve /absolute/registry /absolute/daemon.sock`.
   Existing workspaces, contexts, exports and request journals remain valid.
5. Replace the installed skill with the complete new folder, preserving local
   customizations separately. Native tarballs contain `skills/workgraph/`; the
   RPM installs it at `/usr/share/doc/workgraph/skills/workgraph/`. The standalone
   `workgraph-0.5.2-skill.tar.gz` extracts to `workgraph/`.
6. Update both installed WGX files. If you previously copied only `wgx.sh`, copy
   **`wgx_dashboard.py` beside it**, then quit and reopen the dashboard:

   ```bash
   # Set this to the complete skill folder you just installed.
   SKILL_DIR=/absolute/path/to/workgraph
   mkdir -p "$HOME/.local/bin"
   install -m 755 "$SKILL_DIR/scripts/wgx.sh" "$HOME/.local/bin/wgx"
   install -m 644 "$SKILL_DIR/scripts/wgx_dashboard.py" "$HOME/.local/bin/wgx_dashboard.py"
   export PATH="$HOME/.local/bin:$PATH"
   export WG=/absolute/path/to/workgraph-executable
   export WG_CONTEXT=/absolute/path/to/context.json
   wgx dash
   ```

You may also update only the complete skill and WGX helper while retaining a
0.5.0/0.5.1 executable and running daemon; the API is unchanged. No daemon restart
is needed for a helper-only update. Earlier release assets remain unchanged.

## Upgrade from 0.4 or an older preview

This release does not add migration for pre-0.5 data. Follow the
[preservation-first 0.5 upgrade](v0.5.0.md#upgrade-from-04-or-an-older-preview),
then install 0.5.2. Keep the matching old binary with old data. Do not reset a
working 0.5 installation merely to update the dashboard.

## Dashboard controls

| Key | Action |
| --- | --- |
| Tab / Shift-Tab, left/right, 1–5 | Change views |
| Up/down or j/k | Select an item |
| Enter / Escape | Open details / return |
| PageUp/PageDown, b/space, g/G | Page or jump |
| /, a | Search / filter by worker or resolver; empty input clears |
| f, h | Cycle task-state filter / hide inactive agent reports |
| c, d | Collapse a group / inspect selected ticket dependencies |
| p, i, r | Pause/resume / status inspector / refresh |
| ?, q | Help / quit |

Use `wgx dash -p PROJECT` for project tasks and linked requests, or add
`--run RUN` for that worker's eligibility. Agent, activity and storage records
remain workspace-wide and are labeled as such. Use `wgx watch` for a live event
log, `wgx status` for a one-shot view, and `wgx tree TICKET` for dependencies.

## Qualification and limits

Release packages include manifests, checksums, per-platform qualification JSON,
an aggregate `qualification.json` and evidence archives. Qualification binds the
exact source inventory, commit and executable hashes to the published artifacts.
Checks cover formatter/build/test/install, real daemon/socket behavior, terminal
navigation/resize/reconnection/cleanup, complete skill packaging and installed
CLI, export/restore and history workflows.

The dashboard reads independent captured collections, not one global transaction.
Detailed readiness and acknowledgement checks enrich eight tickets per refresh
and restart after planning changes. Coverage and omitted fields remain visible;
uninspected work is never presented as known clear. Recorded run status does not
prove an agent process is alive. WGX observes work; it does not run agents.

AlmaLinux qualification uses fresh x86_64 containers for RPM and tar installs;
it does not qualify an actual Windows/WSL kernel or SELinux policy. AlmaLinux 10
AMD64 requires x86-64-v3. macOS ARM64 reports record the tested OS and deployment
minimum; Developer ID signing, notarization and browser-download Gatekeeper launch
remain unqualified. No distributed coordination, model runtime or storage
compaction is introduced.
