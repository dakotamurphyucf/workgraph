# Workgraph v0.6.0 preview

Workgraph 0.6.0 improves local agent coordination, bounded reads and recovery after
uncertain writes. It uses application API **0.6**, affected stored roots **5** and
saved upload plan **2**. This is a breaking preview; 0.5 and earlier data and saved
requests are unsupported. Preserve the matching old binary and data before using
fresh current-format roots.

This document describes the release target and implemented contracts. Final
full-suite, installed-package, platform and public-asset qualification are separate
release gates. No published asset, checksum or completed platform run is claimed
by this document. See [validation](../validation.md) for the verification workflow.

## What changed

- Safer typed CLI input, discoverable command examples, consistent preflight
  attribution, useful scalar JSON validation errors and clearer receipt revisions.
  Exact retry journals identify the saved operation and preserve uncertainty.
- Better setup for another actor in an existing workspace; explicit workspace-name
  conflicts; immutable task/context views and read-only candidate eligibility
  without manufacturing probe runs. Actual acquisition remains authoritative.
- Registered and observed participant discovery distinguishes catalog entries from
  retained attributed writers. Observation age, unknown/regressed clocks and
  whole-run held-work counts help harnesses inspect stranded work without inferring
  that a process stopped.
- Full attributed activity expansion and exact pagination metadata. Consumers
  retain each page family's guard, source, selectors and byte-budget continuation;
  a bounded result is never silently presented as a complete history.
- Questions can use existing discussions, retain exact answer pins and expose
  bounded summaries. Attention, durable requests and inbox delivery have separate
  purposes and cursor/acknowledgement lifecycles.
- Text publication, explicit resource linking, UTF-8-safe bounded reads and upload
  staging discovery/recovery. Immutable content versions and metadata revisions
  remain distinct. Saved transfer plans retain explicit upload identity.
- Canonical template publication and preview, explicit project/milestone placement,
  capability/actor policies and deterministic instance identity. Expanded operations
  still fit one bounded atomic planning transaction; no automatic splitting.
- Explicit ticket recovery disposition (`preserve_status` or `requeue`) with
  atomic claim/attempt/reservation cleanup and preserved holds. Advisory contention
  waiters and expected-release notes expose coordination intent without FIFO,
  automatic grants, ownership stealing or lease renewal.
- Shared-input cache and focused agent/terminal views use bounded authoritative
  reads. The harness continues to own process launches, provider backoff, source
  isolation, tool execution and external side effects.

See the [current contract guide](../preview-0.6-contracts.md) and
[feedback coverage](../acceptance/v0.6-feedback.md) for operating boundaries.
SQL-style queries, a model runtime, MCP server, distributed scheduling, automatic
ownership takeover and general compatibility readers remain outside this release.

## Install

Use a matching source checkout until the release assets are published. Planned
native packages are AlmaLinux 10 x86_64 RPM/tar and macOS ARM64 tar, with source and
standalone agent-skill archives. Installation commands in the
[WSL/AlmaLinux guide](../wsl-quickstart.md), [macOS guide](../macos-install.md) and
[skill guide](../agent-skill.md) name v0.6.0 assets and must be used only after those
assets and their evidence exist. Native executables need no OCaml/opam install.
Verify the exact selected filename against the release's `SHA256SUMS`, then verify
`workgraph --version` prints `0.6.0` and `initialize` reports the expected formats.

WGX helpers require Bash and jq; Python dashboard functionality has its own
requirements described in the matching [WGX guide](../../skills/workgraph/references/wgx.md).
Copy the complete current skill directory and companion files together; do not
merge old generated references into the new bundle.

## Upgrade from 0.5 or an older preview

1. Identify the actual old executable, daemon socket, registered and custom
   workspace roots, contexts, request journals and launchers. Preserve its native,
   source and skill archives. Replacing an RPM may replace `/usr/bin/workgraph`.
2. Use that **old executable** to inspect or retry uncertain operations with their
   unchanged saved requests. Preserve any unresolved uncertainty and its journal;
   a new mutation ID or new API marker cannot establish the old outcome.
3. Export and verify needed data with the old executable. Stop custom launchers,
   drain work and shut down the old daemon gracefully. Preserve complete stopped
   registry/workspace roots, contexts, journals, logs and exports separately.
   Verification is preservation, not a cross-version restore path.
4. Install the verified 0.6.0 executable separately where possible. Create new
   private registry/workspace directories, socket, contexts and request journals.
   Never point 0.6 at old managed roots, edit version markers or copy old managed
   JSON into the new tree. Old exports cannot be restored by the new format.
5. Recreate selected plans and context through explicit new current-format records.
   Keep old evidence under its original matching reader. Register only real new
   invocations and retain the actual new claim/attempt/fence receipts.
6. Replace the complete skill and WGX helpers with matching versions, preserving
   local customizations separately. Retarget launchers deliberately. If returning
   to the old version, use only its preserved old roots and endpoint.

No deletion is required. Removing an RPM does not remove custom workspace roots;
never broadly delete directories, sockets or locks to force an upgrade.

## Format boundary

| Representation | 0.6.0 identifier |
| --- | --- |
| Application requests and saved retry envelopes | `workgraph_api:"0.6"` |
| Registry, workspace descriptor, planning transactions/events | `version:"5"` |
| Workspace and workspace-set export manifests | `version:"5"` |
| Saved CLI upload plan | `transfer_version:"2"` |
| Independent planning HEAD, history HEAD/batch and heartbeat cache | `version:"1"` |

Only complete current shapes are supported. Independent unchanged identifiers do
not make older outer roots or saved requests compatible. See
[format and retry contracts](../../skills/workgraph/references/compatibility.md).

## Qualification and limits

Implementation proofs and focused tests cover the reviewed changes. Release
qualification must additionally bind the final commit, exact source inventory,
executables, complete skill/generated references, package manifests and checksums
to observed full-source and installed-platform checks. Root records those results
separately; add exact artifacts and hashes only after they have been produced.

AlmaLinux container qualification does not qualify an actual Windows/WSL kernel
or SELinux policy. macOS deployment minimum, tested OS, signing, notarization and
Gatekeeper behavior require explicit matching evidence. A prior release's platform
record does not qualify this executable.

The service remains local and cooperative. Retained ownership is never removed
by observation age or advisory expiry. Transactions allow at most 32 expanded
operations; facts allow at most 4096 canonical JSON bytes; advisory contention
retains at most 1000 natural keys for the workspace lifetime, including inactive
keys. These are explicit bounds, with no silent cleanup scheduler or fence eviction.
