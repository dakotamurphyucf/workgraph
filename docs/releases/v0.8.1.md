# Workgraph 0.8.1 — HTTP connection reuse

This patch improves the optional browser UI's connection handling. The companion
now keeps HTTP/1.1 connections open for successive requests, allowing the browser
to reuse them for assets, API calls, and live updates.

## What changed

- **Fewer new connections.** Successful sequential requests reuse an existing
  connection instead of closing it after every response. Browsers can still use
  several connections for parallel requests.
- **Fresh limits for each request.** Header accounting and deadlines reset after
  each response. Active connections can serve repeated requests beyond the old
  420-second connection lifetime limit. Idle connections close after 90 seconds
  without complete request headers.
- **Request isolation is preserved.** Each request checks its own authority,
  origin, capability, and body framing. Explicit close requests, HTTP/1.0,
  authorization failures, and invalid request framing still close the connection.
  HTTP pipelining remains unsupported.
- **Cancellation and write recovery are preserved.** Disconnecting releases
  pending reads. Already admitted writes retain their existing durable execution
  and recovery behavior.
- **Clearer introduction.** The README now explains Workgraph as shared planning,
  coordination, and persistent memory for people, agents, applications, integration
  scripts, and automated systems. The bundled agent overview has the same update.

In a local Chrome check, 50 consecutive API requests reused one TCP connection,
with no browser errors. The initial page load used two connections. These are
observed results from that check, not a fixed connection count for every page or
browser.

## Upgrade from 0.8.0

**No workspace reset or data migration is required.** Stop the old UI companion,
resolve uncertain operations with their original executable, and deliberately
stop or hand off the daemon. Install the **0.8.1 UI and core together**, then restart
using your existing workspace, registry, and UI state locations. Keep private
data outside installation directories and preserve saved request journals.
Update the agent skill alongside the executable.

The companion requires an exact package-version match with its daemon. Application
API **0.7**, workspace/export format **6**, history batch format **2**, saved upload
plan **2**, and registry/planning event format **5** are unchanged. Existing 0.7.0
data is also supported without conversion. The separate [offline converter](../migration.md)
remains limited to the released 0.6.2 representation.

Existing 0.8.0 release assets remain unchanged. Removing the optional UI leaves
workspace data and the separately installed core intact.

## Qualification and limits

The change includes real TCP regressions for repeated reads and writes, fresh
header limits, invalid later requests, explicit close, HTTP/1.0, disconnect
cancellation, and repeated long observations followed by idle closure. Release
checks cover formatting, core and optional-UI build/test/install, native package
installation, and browser behavior. Exact package hashes and platform results
are recorded in the attached reports.

macOS packages target ARM64 and are not Developer ID signed or notarized. Native
Safari and Windows-browser-to-WSL operation are not part of this release's automated
qualification. AlmaLinux 10 packages require an x86-64-v3-capable AMD64 CPU. The
browser UI's HTTP connections are separate from the daemon's Unix-socket protocol.
