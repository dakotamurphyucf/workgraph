# Local execution evidence

The Workflow **Local execution evidence** tool inspects stages that an external host or harness already created. This tool does not execute the recorded command; it inspects its saved inputs and outputs. Paths identify files on the companion host, not the browser machine. Literal arguments, working directory, completion outcome and source-provenance coverage remain visible; inspecting a stage does not assert approval, current process liveness or successful execution.

A finished native stage retains `command.json`, `owner.json` and `capture.json`. An unfinished stage has no fabricated completion. Output inspection uses native byte ranges or a tail of the retained prefix, at most 65,536 bytes per read. Retained bytes, total observed bytes, SHA-256, EOF and truncation are independent. A retained tail cannot recover a discarded process suffix. Text may contain replacement characters; the raw bytes and verified download remain exact. Download assembles one capture-bound stream in a worker, verifies its complete retained size and digest, and only then offers a Blob. Changing stage or stream cancels and clears the previous download.

## Publish a saved capture

Select the actual connection and workspace, inspect the stage, and choose **Prepare publication**. Enter the resource ID, expected resource metadata revision and title. Revision 0 means an independently known absent resource; absence from a partial list does not establish it. An optional ticket ID requests a separate link after publication. Review captures the original profile generation/socket, workspace, writer actor/run, immutable capture digest, resource guard and identities before asynchronous work. Later actor, profile or workspace changes do not retarget that preparation.

Review saves a local helper binding before materializing the exact native `publication.json`. It sends no daemon mutation. **Publish resource** explicitly starts the service-owned invocation. Each explicit start, exact retry or receipt recovery qualifies the retained daemon package once within the invocation deadline. An HTTP disconnect or browser navigation stops observation, not an already admitted publication. The UI makes finite read-only observations; it never automatically retries a mutation. Use **Inspect publication** after observation stops or a response is lost.

Resource publication and optional ticket linking are separate. A committed resource remains known while linking is in progress, rejected or uncertain. The UI does not describe an uncertain link as rejected or discard a known publication after transport failure. **Retry exact saved intent** retains the upload, finish and link identities, attribution, guards and bytes. It does not refresh guards, recapture source or rerun execution. A repeated explicit start coalesces with the existing flight. Restart never resumes a flight automatically.

**Recover receipts only** reads the exact original receipts and checks request hashes and acknowledgements. It sends no upload or link mutation and can recover a publication after `capture.json` was removed. Missing receipts mean unknown, never unsent. Local save acknowledgement failure requires **Finish saving exact preparation**, with the same immutable input; a new identity is not a repair. Saved history returns compact pages of at most 25 intentions; exact inspect retrieves the full original plan and receipts.

## Existing external publication intents

The native CLI can already have saved or sent `publication.json`. Its format does not record the original daemon endpoint. Inspection therefore defaults to read-only. **Associate saved intent with this endpoint** is a separate explicit operator assertion. It durably binds the chosen exact retained profile without sending a request, preserves the original actor/run/workspace/resource/guards and bytes, and starts in **Publication outcome unknown**. Association does not prove the chosen endpoint was original, authenticate a daemon process, or claim the intent was unsent. Conflicting associations or changed bytes are refused. Only subsequent explicit receipt recovery or exact retry contacts the chosen daemon.

## Owned cleanup and limits

**Clean owned stage** deliberately delegates to native cleanup using the exact ownership token. It removes only validated native stage files. It refuses unfinished, unmarked, locked/live, symlink, unknown-entry and publication-intent stages. It never recursively deletes arbitrary directories or deletes published resources. Partial failure or a lost reply is not success and never triggers automatic second cleanup.

The companion retains at most 100 immutable publication intentions and admits one publication flight and one bounded inspection at a time. Native command/output/capture bounds remain authoritative; public HTTP job inspections use the existing 16 MiB inspection budget. Cancelled reads and worker failures stay distinct from malformed input. Unexpected exceptions remain visible. These cooperative local paths and retained socket profiles are provenance and concurrency boundaries, not OS process authentication or a command execution service.
